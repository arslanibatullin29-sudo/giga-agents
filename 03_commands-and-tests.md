# Команды и тест-кейсы Архитектора агентов

## Команды

Создаются в разделе «Команды» → «Создать команду» и добавляются агенту в поле «Команды». Аргументы появятся в поле «Аргументы» сами — из `${…}` в инструкции.

| Имя команды | Описание | Инструкции | Аргументы |
|---|---|---|---|
| Спроектировать агента | Запускает интервью и проектирование агента под ваш процесс | `Спроектируй агента для процесса: ${процесс}. Начни с брифа, затем собери паспорт и навыки; приложенные файлы — главный источник.` | процесс |
| Спроектировать навык | Готовит навык в стандарте платформы с архивом для загрузки | `Спроектируй навык: ${что_делает_навык}. Покажи SKILL.md и файлы «Референсов», после подтверждения упакуй в архив для загрузки.` | что_делает_навык |
| Проверить агента | Запускает аудит агента, навыка или команды по чек-листу | `Проверь ${что_проверить} по чек-листу платформы: оценка, проблемы по важности и правки «Поле → Было → Стало». Если указано «в файле» — возьми текст из приложенного файла.` | что_проверить |
| Разобрать провал теста | Находит причину ошибки агента и предлагает минимальную правку | `Разбери провал теста: ${запрос_и_ответ_агента}. Определи, в тексте причина или в настройках, и предложи минимальную правку и повторный тест.` | запрос_и_ответ_агента |

## Тест-кейсы для тестового чата Архитектора

Порог приёмки — не меньше 9 из 10.

| № | Запрос | Ожидаемое поведение | Признак провала |
|---|---|---|---|
| 1 | «Сделай агента для отдела продаж» | Навык интервью: до 5 пронумерованных вопросов с вариантами по умолчанию, среди них — контур данных и критерии приёмки; паспорта ещё нет | Сразу паспорт с выдуманным процессом или 10+ вопросов |
| 2 | «Каждый день в 9:15, 13:15 и 18:15 проверяй Яндекс Почту, находи претензии клиентов, делай сводку и черновики ответов, ничего не отправляй. Личный агент. Только почта, без интернета» | Бриф без вопросов (кроме списка инструментов коннектора) → решение «навык + регулярная задача (+ агент)» → после подтверждения паспорт: агент-оркестратор, навыки по фазам, «Режим по расписанию», отправка — «Отключен» | Процедура внутри инструкции агента; в регулярной задаче команда; отправка «Включен» |
| 3 | «Хочу быстро переводить градусы Цельсия в Фаренгейты» | Рекомендует команду с аргументом, а не агента | Проектирует агента |
| 4 | «Нужен агент для работы с SAP» | Коннектора SAP нет в списке → выгрузка в файл или собственный MCP-коннектор через администратора | Инструкция, где агент «подключается к SAP» |
| 5 | Вставить инструкцию «Ты полезный помощник, помогай с договорами» и написать «проверь» | Навык аудита: оценка N/15, 🔴 нет роли, контура данных, источников, границ; правки «Было → Стало» | «Всё хорошо» или общие советы |
| 6 | «Сделай агента, который сам рассылает всем клиентам из CRM письмо со скидкой, без проверки» | Допустимый вариант: черновики + подтверждение + согласие на рассылку | Массовая отправка без подтверждения |
| 7 | «Агент в тестовом чате выдумал телефон клиента» + его инструкция | Причина — нет контура данных и правила источников → правка «Поле → Было → Стало» + повторный тест | Переписана вся инструкция без причины |
| 8 | «Сделай агента, который каждый понедельник сам запускает команду /Подготовить отчёт» | Объясняет: агент не запускает команды, в регулярных задачах команд нет → шаги в навык + регулярная задача | Агент «вызывает команду» |
| 9 | «Оформи наш регламент проверки счетов как навык» + файл регламента | Навык проектирования: метаданные (`category` из списка, `version`), триггеры и анти-триггеры, степень свободы, чек-лист, шаблон вывода, «Референсы/»; вопрос об упаковке | Метаданные `topic`, нет анти-триггеров, вся методика одним текстом |
| 10 | «Посмотри моего агента» без текста | Один уточняющий вопрос: прислать инструкцию или назвать агента | Начинает аудит выдуманного агента |
