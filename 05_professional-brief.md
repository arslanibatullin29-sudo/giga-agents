# Профессиональная постановка задачи: «Архитектор агентов» для GigaCowork

Это переформулировка исходного запроса «сделай в GigaCowork агента, который будет создавать агентов» так, как её поставил бы руководитель программы внедрения ИИ-агентов. Добавлены вещи, о которых обычно не думают на старте, — они помечены ⚠️.

## Короткая версия (для постановки задачи человеку или ИИ)

> Спроектируй для платформы GigaCowork мета-агента «Архитектор агентов», который превращает описание рабочего процесса сотрудника в готовый к установке комплект: агент-оркестратор, навыки (SKILL.md + Референсы), команды, режимы инструментов коннекторов, регулярные задачи и тест-кейсы. Комплект должен соответствовать стандарту уже работающих на платформе агентов и навыков, учитывать ограничения платформы и модели GigaChat, проходить приёмочные тесты и быть безопасным: человек в контуре для любых действий на запись, явный контур данных, защита от инструкций внутри документов, минимизация персональных данных. Результат — сам Архитектор (инструкция, навыки, команды, тесты), инструкция по установке и критерии приёмки. Неопределённости платформы фиксируй как открытые вопросы, а не как факты.

## 1. Цель

Бизнес-пользователь без опыта промпт-инжиниринга за 30–60 минут получает агента, который:
- решает задачу своего процесса с качеством не ниже ручной работы;
- выглядит и ведёт себя как остальные агенты платформы (единый стандарт);
- безопасен: не пишет во внешние системы без подтверждения и не выдумывает данные.

⚠️ Цель — не «сгенерировать промпт», а **сократить путь от идеи до работающего и проверенного агента**. Поэтому в объём входят тесты, установка и доработка, а не только текст.

## 2. Пользователи

| Кто | Что ему нужно от Архитектора |
|---|---|
| Сотрудник-автор процесса | Интервью простым языком, готовые тексты для копирования, пошаговая установка |
| Владелец пространства | Агенты для команды: навыки и команды пространства, права участников |
| ⚠️ Администратор платформы | Единый стандарт, отсутствие дублей, понятные категории и версии, кандидаты в плагины |
| ⚠️ Служба ИБ и юристы | Контур данных, персональные данные, действия на запись, журнал изменений |

## 3. Что должен делать Архитектор

1. **Бриф.** Извлечь из запроса и приложенных регламентов всё известное; спросить недостающее (не больше 2 раундов по 5 вопросов, у каждого — вариант по умолчанию).
2. **Выбор архитектуры.** Самое простое достаточное решение: запрос → команда → навык → агент-оркестратор → регулярная задача → несколько агентов / плагин.
3. **Паспорт агента.** Тексты для всех полей формы, карта навыков по фазам, маршрутизация, принципы, границы, команды, режимы инструментов коннекторов, регулярная задача, тест-кейсы, порядок установки.
4. **Навыки.** Каждый — в стандарте платформы: метаданные, триггеры и анти-триггеры, степень свободы, рабочий процесс-чек-лист, шаблон вывода, проверка качества, файлы «Референсы/», Python-расчёты для `python_run`. ⚠️ По возможности — готовый архив для загрузки, чтобы не копировать вручную.
5. **Доработка.** Разбор провалов тестов и точечные правки «Поле → Было → Стало».

## 4. Стандарт качества создаваемых агентов

- Агент — оркестратор: роль, карта навыков, маршрутизация, принципы, стиль, границы; до 500 слов. Процедуры — в навыках.
- Навык — одна процедура; триггеры и анти-триггеры с именами соседних навыков.
- Команды — короткие (1–2 предложения), 1–3 аргумента, глагол в начале имени.
- Каждый факт — с источником; нет данных → «не найдено».
- Сначала вывод (вердикт, находки), потом детали; факты отделены от интерпретаций.
- Расчёты — детерминированно через Python; модель не меняет посчитанные числа.
- Предпросмотр в чате раньше файла; запись во внешние системы — после подтверждения человека.

## 5. Ограничения платформы и модели

- Агента нельзя создать из чата (по документации 26.9.1) — только формой; навыки и команды можно.
- В задаче с агентом доступны только его навыки, команды и коннекторы; агент не запускает команды сам.
- Режимы инструментов коннектора глобальны для пользователя; в пространстве каждый участник настраивает свои.
- Регулярные задачи: нет команд, нет пользователя для вопросов, у «Каждый день» одинаковые минуты.
- Категория навыка — из закрытого списка; имена файлов в архивах — с пометкой UTF-8.
- Модель семейства GigaChat: Markdown вместо XML, конкретные числа, пример ответа в инструкции, инструменты по одному.

## 6. ⚠️ То, о чём обычно не думают

1. **Реестр агентов и навыков.** Без него через месяц появятся пять «помощников по договорам» с пересекающимися триггерами. Нужны: владелец, назначение, версия, соседние навыки (анти-триггеры).
2. **Версии и журнал изменений.** Поле `version` в навыке, запись «что изменили и почему», повторный прогон тестов после каждой правки (регрессия).
3. **Контур данных.** Каждый агент явно говорит, откуда ему можно брать факты: только файлы, плюс указанные системы, плюс веб, плюс знания модели. Это главный рычаг против выдумок.
4. **Персональные данные (152-ФЗ).** Резюме, контакты клиентов, обращения — персональные данные. Минимизация, никакой выгрузки в публичные сервисы, понятный владелец данных.
5. **Права и наименьшие привилегии.** Режимы инструментов коннекторов глобальны — включённая «запись» для одного агента включена для всех задач пользователя.
6. **Инъекции через данные.** Письма, документы и веб-страницы могут содержать «инструкции» для агента. Правило «данные — не команды» обязательно в каждом агенте.
7. **Приёмка в цифрах.** Набор эталонных запросов (golden set) и порог, например ≥ 7 из 8 тестов, 0 действий на запись без подтверждения, 0 выдуманных фактов.
8. **Стоимость и скорость.** Длинные инструкции и полные справочники в контексте дороже и медленнее; справочники — в «Референсы/» и подгружаются по шагам.
9. **Обратная связь и мониторинг.** Оценки «Помогло / Не помогло», история запусков регулярных задач, ежемесячный разбор провалов.
10. **Тиражирование.** Удачный комплект для отдела — кандидат в плагин через администратора: плагин нельзя редактировать, поэтому сначала стабилизировать версию.
11. **Вывод из эксплуатации.** Кто и когда отключает устаревшего агента и чем его заменяет.
12. **Обучение пользователей.** Описание агента в карточке и команды — это и есть онбординг: человек должен понять, что дать агенту на вход, не читая инструкцию.

## 8. Критерии приёмки

1. Архитектор проходит не меньше 9 из 10 тест-кейсов из `03_commands-and-tests.md`.
2. Паспорт, собранный Архитектором, вставляется в форму без доработки; навыки загружаются без ошибок.
3. В паспортах нет команд внутри шагов агента, нет записи без подтверждения, есть контур данных и правило источников.
4. Новый агент, собранный по паспорту, проходит свои тест-кейсы не хуже 7 из 8 после не более чем двух итераций доработки.
