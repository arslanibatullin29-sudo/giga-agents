# Практики и скрытые правила из действующих агентов GigaCowork

Разбор нескольких действующих агентов, навыков и команд платформы из разных функций. Примеры обобщены: конкретные тексты, названия и данные не приводятся.

## 1. Скрытые факты о платформе

Их нет в пользовательской документации, но они видны в работающих навыках.

| Факт | Где видно | Что это значит |
|---|---|---|
| Метаданные SKILL.md — `category`, `version`, `name`, `description` | Markdown-режим навыка | Документация называет поле `topic`, на деле используется `category`; есть поле `version` |
| `category` — из закрытого списка, латиницей (например, `sales`) | Метаданные + ошибка загрузки «Выберите категорию из списка» | Произвольную категорию указать нельзя |
| Python запускается инструментом `python_run` | «Прочитай код из `Референсы/calculate.py` и передай его в `python_run`» | Код хранят файлом в навыке, а не вставляют в инструкцию |
| Рабочая папка задачи — `/session` | «Промежуточные файлы — в /session, сообщай путь пользователю» | Сюда сохраняют черновики, таблицы, JSON |
| Папка ресурсов навыка — `Референсы/` | Дерево файлов навыков | Методики, JSON-схемы, справочники, `.py` |
| Системные навыки: «Работа с Excel (.xlsx)», «Работа с Word (.docx)», «Работа с PDF», «Работа с PowerPoint (.pptx)», «Полнотекстовый поиск», «Знания пространства», «Файлы воркспейса», «Инфографика» | Карточки агентов | Точные названия для ссылок из инструкций |
| Плагин может нести данные в папке `Данные/` | Инструкция одного из агентов | Справочники для «закрытого контура» данных |
| У команды есть поле «Аргументы» | Карточки команд | Аргументы выводятся из `${…}` в инструкции |
| Навыки в инструкциях агентов называют по slug (`lead-intake`) рядом с русским названием | Инструкции агентов | Удобно для однозначной ссылки |
| Чек-лист «Прогресс …» в навыке | Навыки с многими шагами | Совпадает с компонентом «Прогресс» в задаче |

## 2. Устройство агента

Агент — **оркестратор навыков**, а не носитель процедуры. Инструкция занимает 300–450 слов и состоит из:
1. Одной фразы «Ты — … : …».
2. **Роли** с явной оговоркой: публичные действия и решения выполняет только человек, агент готовит материалы.
3. **Карты навыков**: таблица «Фаза → Навык → Результат» или список по фазам; плюс «типовая цепочка» навыков.
4. **Маршрутизации** из четырёх правил: один навык → вызвать; составной запрос → цепочка и единая сводка; неоднозначно → один уточняющий вопрос, не наугад; вне навыков → сказать и направить к специалисту.
5. **Принципов**: человек в контуре; прослеживаемость (факт → источник, иначе «данные отсутствуют»); противоречия источников — перечислить и спросить; закрытый контур данных; факты отдельно от интерпретаций; промежуточные файлы в `/session`.
6. **Стиля** и **границ** (что вне зоны ответственности и к кому идти).

Калибровка вопросов зависит от типа задачи: рутина (саммари, письма) — без лишних вопросов, аналитика — уточнить период и источник.

## 3. Устройство навыка

Два варианта одного стандарта:

**Аналитический навык** (расчёты): Предусловия → Не использовать → Рабочий процесс (чек-лист) → Инварианты → Выход (именованные блоки результата: `data_quality`, `evidence`, `limitations` …) → Исполнение расчёта (`python_run`) → Ресурсы.

**Процедурный навык**: Когда использовать (триггеры) → Анти-триггеры со ссылками на соседние навыки → Роль → Принципы → Рабочий процесс (шаги + «Степень свободы» + конвенция рабочей папки) → Шаблоны вывода → Проверка качества → Тон и стиль → Справочники.

Общие правила:
- **Степень свободы** объявлена явно: низкая в расчётах и форматах, средняя в интерпретации.
- **Описание (`description`)**: что делает + «Используйте при запросах «…»» + неформальные формулировки пользователей.
- **Анти-триггеры** называют соседние навыки по имени — так навыки не перехватывают чужие запросы.
- **Модульность внутри навыка**: таблица «Что нужно → Модуль → Файл в Референсы/»; файл подгружается только на нужном шаге.
- **Инварианты**: знаменатели и допущения явные, пропуски не додумываются, модель не меняет посчитанные числа.
- **Промежуточные артефакты по JSON-схеме** (стратегия, список, результат) — прослеживаемость и повторяемость.
- **Предпросмотр раньше файла** и **контрольная точка с человеком**: «Продолжить или сформировать отчёт?».
- **Вывод «сначала вердикт»**: диагноз → таблица → точки внимания с флагами 🔴🟡🟢 → рекомендации с приоритетом и эффектом в деньгах.
- **Разделение «подтверждено источником» / «требует проверки»**, пометка «(оценочно)» для бенчмарков.

## 4. Устройство команды

- Имя — глагол в инфинитиве: «Оформить …», «Проверить …».
- Описание — «Запускает … / Собирает …» одной строкой.
- Инструкция — 1–2 предложения, 1–2 аргумента; логика живёт в навыке, команда только запускает его с параметрами.
- Аргументы — понятные имена: `${проблема}`, `${файлы_или_папка}`, `${вакансия}`.

## 5. Что изменено в Архитекторе (версия 5)

| Было | Стало |
|---|---|
| Один большой навык-справочник | 4 навыка по фазам: интервью и архитектура → паспорт → навык → аудит |
| Инструкция Архитектора ~2 600 слов с процедурами | Оркестратор ~730 слов: роль, карта навыков, маршрутизация, справка о платформе, принципы, границы |
| Генерируемые агенты с процедурой внутри инструкции | Генерируемые агенты — оркестраторы; процедуры — в навыках (работают и в регулярных задачах) |
| Шаблон «Когда применять» из документации | Формула описания и анти-триггеры, как в действующих навыках |
| `topic` | `category` + `version` |
| Python в тексте инструкции | Код в `Референсы/*.py`, запуск через `python_run` |
| Ручное копирование навыков | Упаковка навыка в архив через `python_run` (если доступно) + архивы в репозитории |
| Команды на 5–8 строк | Команды на 1–2 предложения с аргументами, имя-инфинитив |
| Нет контура данных | Контур данных — обязательное поле брифа и принцип каждого агента |
| Нет промежуточных артефактов | Бриф и паспорт сохраняются в `/session/<slug>/` |
