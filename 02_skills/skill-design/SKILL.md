# Проектирование навыка GigaCowork

**Степень свободы:** низкая в формате файла, метаданных и упаковке; средняя в содержании методики.

## Когда использовать
- Нужен навык из паспорта агента или отдельный навык под процедуру.
- Нужно превратить регламент, методику или чек-лист в навык.
- Нужна команда — короткая точка входа в навык.
- Навык не загружается или не срабатывает из-за метаданных.

## Анти-триггеры
- Нужен агент целиком → «Сборка паспорта агента».
- Нужно понять, что вообще автоматизировать → «Интервью и выбор архитектуры агента».
- Агент работает, но ошибается на тестах → «Аудит и доработка агента».

## Принципы
- **Одна процедура — один навык.** Три простых навыка лучше одного общего.
- **Описание — это условие вызова.** Что делает + «Используйте при запросах «…»» + неформальные формулировки. Общие слова «помоги», «сделай», «расскажи» — только вместе с объектом («сделай отчёт по воронке»), не как самостоятельный триггер.
- **Анти-триггеры называют соседей по имени**, чтобы навыки не перехватывали чужие запросы.
- **Справочники — в «Референсы/»**, в SKILL.md — когда какой файл читать. Файл подгружается только на нужном шаге.
- **Расчёты — кодом.** Код — файлом `Референсы/<имя>.py`, запуск через `python_run`; модель не меняет посчитанные значения.
- **Без выдумок.** Каждый факт — с источником; нет данных — «не найдено».
- **Предпросмотр раньше файла**, запись — после подтверждения человека.

## Рабочий процесс
- [ ] Определить одну процедуру навыка, его соседей и вход/выход.
- [ ] Выбрать степень свободы: низкая (расчёты, форматы, регламент), средняя (каркас + адаптация), высокая (тексты, идеи).
- [ ] Выбрать вариант шаблона: аналитический (расчёты) или процедурный (шаги с людьми и системами) — `Референсы/ШАБЛОН_НАВЫКА.md`.
- [ ] Написать метаданные по правилам ниже.
- [ ] Написать тело навыка; многошаговую процедуру сопроводить чек-листом прогресса.
- [ ] Вынести в «Референсы/» методики, справочники, шаблоны, JSON-схемы результата и Python-код.
- [ ] Если нужны команды — по `Референсы/ШАБЛОН_КОМАНДЫ.md`.
- [ ] Пройти «Проверку качества».
- [ ] Показать навык в чате. После подтверждения — упаковать (раздел «Упаковка») или предложить создать навык прямо в чате.

## Правила метаданных
- Порядок полей: `category`, `version`, `name`, `description`.
- `category` — значение из списка категорий платформы (латиницей; подтверждено `sales`). Если список неизвестен — спроси пользователя или напиши «выбрать из списка».
- `version` — целое число; увеличивай на 1 при каждом изменении поведения навыка.
- `name` — по-русски, 2–5 слов, существительное: «Анализ дебиторской задолженности».
- `description` — до 500 знаков; если есть двоеточия — заключи значение в кавычки.

## Упаковка
1. Сохрани файлы навыка в `/session/<slug>/`: `SKILL.md` и папку `Референсы/`.
2. Прочитай код из `Референсы/pack_skill.py`, подставь `SLUG = "<slug>"` и передай в `python_run`.
3. Скрипт проверит метаданные и соберёт `/session/<slug>.zip` с именами файлов в UTF-8. Покажи пользователю найденные проблемы или путь к архиву.
4. Пользователь загружает архив: «Навыки → Создать навык → Загрузить файл навыка».

Если `python_run` недоступен или упаковка не удалась — выдай SKILL.md и файлы «Референсов» по отдельности и инструкцию: «Создать навык → Написать инструкцию навыка», затем «+» → «Загрузить файл» для каждого файла.

## Шаблон вывода
1. Таблица: Название | slug | category | version | Степень свободы | Файлы «Референсов».
2. `SKILL.md` — в блоке кода (четыре обратные кавычки, если внутри есть блоки кода).
3. Каждый файл «Референсов» — отдельным блоком кода с путём в заголовке.
4. Команды — таблица: Имя | Описание | Инструкции | Аргументы.
5. Вопрос: «Упаковать навык в архив для загрузки?»

## Проверка качества
- [ ] Навык делает одну процедуру; есть «Когда использовать» и «Анти-триггеры» с именами соседей.
- [ ] Метаданные полные; `category` из списка; `description` с триггерами в кавычках и неформальными формулировками.
- [ ] Степень свободы объявлена.
- [ ] Рабочий процесс — чек-лист; у каждого шага есть результат.
- [ ] Шаблон вывода с примером или схемой; сначала вывод, потом детали.
- [ ] Правило источников и «не найдено» вместо догадок.
- [ ] Запись во внешние системы — через предпросмотр и подтверждение.
- [ ] Каждый файл из «Референсов» упомянут в SKILL.md с указанием, когда его читать.
- [ ] Расчёты — в `.py` через `python_run`; инвариант «модель не меняет числа».
- [ ] Нет оценочных слов без числа; нет XML-тегов.

## Ресурсы навыка
- `Референсы/ШАБЛОН_НАВЫКА.md` — аналитический и процедурный варианты SKILL.md.
- `Референсы/ШАБЛОН_КОМАНДЫ.md` — правила и примеры команд.
- `Референсы/pack_skill.py` — проверка метаданных и упаковка навыка в архив.

Подгружай файл из `Референсы/` только когда он нужен для текущего шага.
