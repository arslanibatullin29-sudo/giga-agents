# Интервью и выбор архитектуры агента

**Степень свободы:** низкая в составе брифа и дереве решений; средняя в формулировке вопросов.

## Когда использовать
- Пользователь описывает процесс и хочет агента или автоматизацию.
- Нужно понять, хватит ли команды или навыка вместо агента.
- Процесс из нескольких ролей нужно разложить на агентов.

## Анти-триггеры
- Бриф уже подтверждён, нужен паспорт → «Сборка паспорта агента».
- Нужен текст одного навыка или команды → «Проектирование навыка GigaCowork».
- Есть готовый агент и он ошибается → «Аудит и доработка агента».

## Принципы
- **Сначала извлеки, потом спрашивай.** Всё, что есть в запросе и приложенных файлах (регламенты, чек-листы, примеры результатов), в вопросы не попадает.
- **Вопросы с ответом по умолчанию.** До 5 пронумерованных вопросов за раунд, не больше 2 раундов; на «не знаю» — значение по умолчанию с пометкой «допущение».
- **Только реальные инструменты.** Шаги с коннектором строятся на инструментах из его карточки. Попроси пользователя перечислить их или прислать скриншот; до этого — пометка «проверить инструмент».
- **Самое простое достаточное решение.**

## Рабочий процесс
- [ ] Прочитать запрос и приложенные файлы; извлечь известное.
- [ ] Заполнить бриф по схеме `Референсы/СХЕМА_БРИФА.json`; пустые обязательные поля превратить в вопросы.
- [ ] Задать вопросы (раунд 1, при необходимости раунд 2).
- [ ] Подобрать типовую роль из `Референсы/ТИПОВЫЕ_АГЕНТЫ.md`, если процесс на неё похож.
- [ ] Выбрать архитектуру по дереву решений и объяснить выбор в 2–4 предложениях.
- [ ] Показать бриф и решение в чате; после подтверждения сохранить `/session/<slug>/бриф.json` и предложить собрать паспорт.

## Бриф — 10 обязательных сведений
1. Результат и его формат: таблица, DOCX, письмо, запись в CRM, ответ в чате.
2. Пользователи и место агента: личный или пространство «…».
3. Входы: что даёт пользователь; что агент берёт сам (коннекторы, документы пространства, веб).
4. **Контур данных**: только файлы и указанные системы / плюс веб-поиск / плюс общие знания модели.
5. Текущий процесс: шаги, правила, нормативы, критерии качества.
6. Действия на запись и кто их подтверждает.
7. Частота: по запросу, командой, по расписанию.
8. Границы и соседи: что агенту запрещено, с какими агентами и навыками нельзя пересекаться.
9. Персональные и чувствительные данные: есть ли, можно ли обойтись без них.
10. Приёмка: 3–5 критериев «агент работает» и пример эталонного результата.

## Дерево решений

| Ситуация | Решение |
|---|---|
| Разовая задача | Хороший запрос в обычном чате, агент не нужен |
| Один и тот же запрос, меняются 1–3 параметра | Команда с аргументами |
| Повторяемая процедура, включается по смыслу, нужна разным агентам | Навык |
| Роль с 2+ процедурами, своими коннекторами и правилами | Агент-оркестратор + по навыку на процедуру + 0–3 команды |
| Работа по расписанию | Навык с процедурой + регулярная задача (агент — по желанию) |
| Несколько ролей с разными данными и правами | Несколько агентов; связь — через документы пространства и человека; для тиражирования — плагин через администратора |

Процедуры всегда кладём в навыки: так они срабатывают без агента, доступны в регулярных задачах и переиспользуются.

## Шаблон вывода

**Бриф: <процесс>**

| № | Сведение | Значение | Источник: файл / ответ / допущение |
|---|---|---|---|

**Решение:** <архитектура> — <почему, 2–4 предложения>.
**Состав:** агент «…» + навыки «…», «…» + команды «…» + регулярная задача «…».
**Допущения:** …
**Открытые вопросы:** … (если остались)

Последняя строка: «Собрать паспорт агента?»

## Проверка качества
- [ ] Все 10 сведений заполнены или помечены «допущение».
- [ ] Контур данных указан явно.
- [ ] Есть критерии приёмки, по возможности — эталон результата.
- [ ] Для каждого коннектора есть список инструментов или пометка «проверить инструмент».
- [ ] Выбрано самое простое достаточное решение, выбор объяснён.

## Ресурсы навыка
- `Референсы/СХЕМА_БРИФА.json` — структура брифа для сохранения в `/session`.
- `Референсы/ТИПОВЫЕ_АГЕНТЫ.md` — 7 типовых ролей: карта навыков, коннекторы, риски.

Подгружай файл из `Референсы/` только когда он нужен для текущего шага.
